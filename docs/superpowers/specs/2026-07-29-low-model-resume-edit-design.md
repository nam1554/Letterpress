# 저모델 튜닝 · 이어하기 · 부분 수정 — 설계 문서

날짜: 2026-07-29
상태: 자율 실행 모드로 확정 (사용자 요청 3건 — 결정 사항은 본 문서에 기록)
선행: `2026-07-29-quality-gate-design.md` (품질 게이트 + 보수 런 메커니즘을 재활용)

## 요청

1. Haiku 같은 저렴한 모델로도 어느 정도 품질이 나오도록 튜닝/최적화.
2. 타임아웃으로 중단된 작업을 **이어서** 시도할 수 있어야 함 (처음부터 재실행 말고).
3. 완성된 eDM에서 **특정 문구나 이미지만** 수정하는 방법.

## 설계

### 1. 저모델 튜닝

**모델 선택 수단** — 설정에 `claudeModel`(자유 텍스트, 빈 값 = CLI 기본)을
추가하고 `claude-code` 프로바이더가 `--model <값>`을 넘긴다. 설정 패널에서
"haiku" 등으로 바꿔 실험한다. (Gemini/Codex는 각자 CLI 기본 모델 사용 — 후속.)

**난이도 상한(핵심 튜닝)** — 약한 모델이 실패하는 지점은 verify FAIL 밴드를
진단해 px 단위로 고치는 반복 루프다. 프롬프트에 **반복 예산 + 플랫 이미지
폴백** 규칙을 명문화한다: 같은 밴드가 빌드→검증 2회 후에도 FAIL이면 그 섹션을
Figma 섹션 노드의 플랫 이미지로 교체하고 재검증. 손으로 못 맞추는 섹션은
이미지가 되므로 어떤 모델이든 픽셀 충실도가 수렴한다 (텍스트가 이미지화되는
비용은 있지만 "동일 품질" 보장이 우선 — 스킬도 레이어드 섹션에 같은 전략을
이미 쓴다).

자동 보수는 1회 유지 (비용 상한). 게이트가 있으므로 저모델의 실패는 허위
성공이 아니라 명시적 실패로 나타난다.

### 2. 이어하기 (resume)

`POST /api/jobs/:id/resume` — `failed` 잡 한정, 동시 실행 캡 적용.
같은 잡·같은 workDir에서 재개한다:

- 잡을 `running`으로 되돌리고 summary/finishedAt/verify를 비운다.
- 현재 `checkAcceptance` 실패 항목을 `task.repair`로 첫 런에 싣는다 —
  "중간 산출물 재사용, 나열된 미충족 항목만 완성"이 곧 이어하기다.
- 새 타임아웃 타이머로 러너 재진입. 게이트→자동 보수 흐름은 동일.

UI: 실패한 잡 페이지에 "이어서 실행" 버튼 추가 ("다시 실행"은 기존대로
새 잡 + 빈 workDir).

### 3. 부분 수정 (문구/이미지)

`POST /api/jobs/:id/edit { instruction }` — 산출물이 있는 종료 잡 대상.

- **새 잡을 만들고** 원본 잡의 `work/`를 통째로 복사한다 (원본 보존, 수정
  이력이 잡 히스토리로 남음). `Job.editOf`(원본 id)와 `Job.instruction` 기록,
  title은 "원본 제목 · 수정".
- 프롬프트는 edit 모드(`task.edit.instruction`): 이미 빌드·검증된 eDM이 cwd에
  있으니 스킬의 "Adapting when copy or design changes" 흐름대로 **지시된
  변경만** 적용 — 문구면 빌드 스크립트 문자열 + 폰트 서브셋 TEXT 갱신, 이미지면
  (지시가 Figma를 참조하면) 해당 노드 재페치 — 후 재빌드·재검증·산출물 갱신.
- **게이트 완화**: 의도적 수정은 원본 Figma와 달라지므로 verify FAIL을 실패가
  아닌 경고로 강등한다 (`checkAcceptance(id, { requireVerifyPass: false })`).
  산출물 계약과 "검증을 실행했다"(증거물 + verify.json 존재)는 그대로 요구.
- UI: 성공한 잡 페이지에 수정 지시 입력창 + 실행 버튼 → 생성된 잡으로 이동.
- 로컬 이미지 업로드 교체는 후속 (지금은 지시문 + Figma 재페치 경로만).

## 트레이드오프 / 결정

- **resume는 같은 잡 재사용, edit은 새 잡** — resume은 "같은 작업의 계속"이라
  이력이 하나여야 하고, edit은 "다른 산출물"이라 원본을 보존해야 한다.
- **플랫 이미지 폴백은 프롬프트 규칙으로** (앱 코드 아님): 판단이 필요한
  전략이라 에이전트 몫이고, 게이트가 결과를 검증한다.
- **claudeModel은 검증 없이 저장** — 잘못된 모델명은 CLI가 즉시 에러를 내고
  stderr tail이 잡 실패 사유로 표시된다.

## 테스트

- prompt.test.ts: repair/edit/모델 프롬프트 조립 검증.
- acceptance: requireVerifyPass=false에서 FAIL이 경고로 강등되는 케이스.
- runner: 실패 잡 resume → mock으로 succeeded 전이, summary/verify 갱신.
- store: edit 잡 생성(workDir 복사) 검증. 기존 스위트 + tsc + lint + build.
