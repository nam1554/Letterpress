## 히스토리 재작성 (완료)

위 1~3번은 작업 트리만 고친 것이라 **과거 커밋을 열면 그대로 보였다.** 공개
전이고 아무도 clone 하지 않은 시점이 재작성 비용이 가장 싸므로, `git
filter-repo`로 107개 커밋 전체를 다시 썼다.

| 항목 | 전 | 후 |
|---|---|---|
| 작성자 이메일 | 개인 Gmail | `nam1554@users.noreply.github.com` |
| 커밋 메시지의 `Claude-Session:` 링크 | 70건 | 0건 |
| 과거 커밋 속 개인 홈 경로 | 다수 | 0건 |
| 과거 커밋 속 사내 Figma 파일 키 | 다수 | 0건 |

- noreply 주소를 쓰면 실제 메일 주소는 감추면서 GitHub 프로필 연결과 커밋
  잔디는 그대로 유지된다.
- 세션 링크는 작성자 계정에서만 열리므로 **정보가 새던 것은 아니다.** 외부
  독자에게는 열리지 않는 죽은 링크라 지웠다.
- **모든 커밋 SHA가 바뀌었다.** 재작성 전 원본은 원격에 백업 브랜치로 잠시
  올려 뒀다가, 검증 후 **삭제했다** — 그 브랜치에는 위 식별자가 전부 살아
  있어서 남겨 두면 이 정리가 통째로 무의미해진다. 원본은 저장소 밖의 로컬
  번들 파일 하나로만 남아 있다:
  `../Letterpress-pre-public-backup.bundle` (원본 HEAD `7e7d2f5`,
  `git bundle verify`로 완전한 히스토리임을 확인). 되살리려면
  `git clone <번들경로>`. **이 파일은 저장소에 넣지 말 것.**

재작성 명령(재현용):

```bash
git-filter-repo --force \
  --mailmap mailmap.txt \        # 개인 주소 → noreply
  --replace-text replace.txt \   # 개인 경로·사내 Figma 키 치환
  --message-callback '...'       # Claude-Session: 줄 제거
```

## ⚠️ 강제 푸시는 GitHub에서 커밋을 지우지 않는다 (실측)

재작성 후 확인해 보니 **저장소는 이미 퍼블릭이었고**(2026-07-29 생성),
재작성 전 커밋이 **여전히 SHA로 공개 조회된다.**

```
$ gh api repos/nam1554/Letterpress/commits/7e7d2f5b5b7… --jq '.commit.author.email'
<개인 Gmail 주소>        # 강제 푸시 이후에도 그대로 나온다
$ gh api repos/nam1554/Letterpress/commits/93eab86 --jq '.commit.author.email'
<개인 Gmail 주소>
```

GitHub은 참조가 끊긴 커밋을 즉시 수거하지 않는다. 브랜치에서 사라져 목록에는
안 보이지만, SHA를 아는 사람은 `/commit/<sha>`로 계속 열 수 있다. 즉 **위
"히스토리 재작성" 표의 효과는 앞으로 clone 하는 사람에게만 적용된다** — 이미
공개돼 있던 2일치 히스토리는 아직 조회 가능하다.

새는 것은 **자격증명이 아니다**(시크릿은 애초에 없었다). 개인 Gmail 주소,
개인 홈 경로, 사내 Figma 파일 키다. 완전히 없애려면 둘 중 하나가 필요하다:

- **저장소 삭제 후 재생성** — 확실하다. 이 저장소는 star·fork·issue·PR이
  모두 0이라 잃을 것이 코드 외에 없다. 정리된 히스토리를 그대로 다시 올리면
  된다.
- **GitHub Support에 gc 요청** — 저장소를 유지한 채 처리할 수 있지만 회신을
  기다려야 한다.

## 히스토리 재작성은 git 설정까지 함께 고쳐야 한다 (실수 기록)

첫 재작성은 **그 시점까지의 커밋만** 고쳤다. 저장소의 `user.email`은 그대로
개인 Gmail이었기 때문에, 그 뒤에 만든 커밋 7개가 개인 주소를 그대로 다시
집어넣었다. 저장소를 삭제·재생성해 옛 SHA를 없앤 직후에 그 7개를 밀어 넣었고,
뒤늦게 알아채고 강제 푸시로 덮었지만 — 바로 위에 적어 둔 그대로 — 강제 푸시는
GitHub에서 커밋을 지우지 않는다. 결국 재생성을 한 번 더 해야 했다.

**재작성할 때 반드시 같이 할 것:**

```bash
git config user.email nam1554@users.noreply.github.com
git config user.name  nam1554
```

저장소 로컬 설정으로 둔다(`--global` 아님) — 다른 프로젝트의 신원까지 바꿀
이유는 없다. 이 설정은 clone 하면 따라오지 않으므로, 이 저장소에 커밋할
사람은 각자 한 번 실행해야 한다.

**순서가 중요하다:** 로컬 히스토리를 완전히 정리하고 **그 다음에** 처음 푸시한다.
푸시한 뒤 고치면 밀려난 커밋이 SHA로 남아, 저장소를 또 지워야 한다.
